# JTML v0.3 candidate support matrix

Status: **proposal; owner approval pending**. Evidence inspected on 2026-10-18
at main `0c9adc9a96a7dd3c04954bdc0c26b345a3374868` (PRs #1–#10 integrated).
This document neither freezes the surface nor declares v0.3 ready. No release
date or external adoption threshold is proposed.

The target is an experimental research preview of Friendly JTML 2. Classic
compatibility/live/C API support remains intact; JTL remains experimental.
Compiler ownership stays Friendly → AST / Expression IR → Semantic IR /
observable graph → Runtime Plan → backends. See [architecture](../../ARCHITECTURE.md),
[semantic roadmap](../architecture/observable-first-architecture-roadmap.md),
[language family](../architecture/language-family-design.md), and
[implementation order](../roadmaps/next-priorities.md).

## How to read the evidence

- **SUPPORTED CANDIDATE**: a bounded behavior has explicit verification evidence;
  proposed for the preview promise, subject to owner approval and fresh gates.
- **EXPERIMENTAL**: implemented in part, with stated limits; no blanket clean
  production promise.
- **UNSUPPORTED**: outside the proposed clean production promise. Each entry
  distinguishes tested rejection from a fail-closed gap or unaudited boundary.
- **UNVERIFIED**: evidence is insufficient to classify behavior. Acceptance by
  syntax or build alone is not support and is not proof of rejection.

These labels apply to the named shape/backend, not an entire keyword. Existing
verified supported behavior must remain covered; an owner cannot resolve a
failing supported regression merely by relabeling it. Parser tests, examples,
roadmap checkmarks and doctor metadata are discovery aids, not browser proof.
Test sources below are inspected evidence, not a claim that this documentation
PR reran them. Historical execution records are in
[CURRENT_STATE](../../CURRENT_STATE.md) and the
[conditional implementation note](../architecture/conditional-reactivity.md).

## Candidate matrix

Evidence IDs link to the exact test files above. Every decision below is pending;
“retain” means preserve its current tested contract while deciding preview scope.

| Feature / proposed classification | Precise boundary and evidence | Missing tests / known defects or uncertainty | Required release decision |
| --- | --- | --- | --- |
| Scalar state and derived values — **SUPPORTED CANDIDATE** | Component-local `let` assignment and `get` over statically compiled expressions; repeated changes propagate through derived reads to DOM. E1, E2, E10; derived closure uses worklists (E13). | No full typechecker/nullability contract; exhaustive coercion, invalid arithmetic and cycle behavior are not established by these fixtures. | Retain tested scalar/derived behavior; publish operand/type boundaries and decide cycle/error requirements. |
| Arithmetic, comparison, logical expressions — **SUPPORTED CANDIDATE** | Bounded number/string/boolean cases in E1/E2: arithmetic combinations, equality/inequality, ordering, `&&`, `\|\|`, `!`, member/index reads. Both operands contribute dependencies even when inactive. | Operator syntax coverage exceeds independent browser value assertions. NaN, infinity, division by zero, mixed types, missing paths and every operator combination need a declared policy and tests. | Retain bounded expression support; do not infer universal JavaScript semantics. Approve an explicit value/operator table before freeze. |
| Conditional branches and ternaries — **SUPPORTED CANDIDATE** | Statically compiled `if`/`else`, ternaries and derived conditions union both branches; repeated false→true→false changes update nested UI. Same-branch children retain identity/state; transitions destroy and recreate. E1–E3. | PR #10 fixed stale comparison dependencies and child-generation loss; these are historical defects, not current known failures. Wider exception/call conditions are outside this boundary. | Retain the mandatory dependency/lifecycle regressions and original-code negative controls. |
| Component parameters, nesting and slots — **SUPPORTED CANDIDATE** | Scalar and object parameter updates on tested static paths; two-level text/attribute propagation, independent siblings, direct nested creation. E2, E7, E10; slot plans in E12 and semantic tests `ComponentInstancesCarryAuthoredSlotPlansAndSplitParams`. | Slot metadata coverage is broader than composed adversarial browser proof; typed slot/event payloads and complex slot lifecycle need more tests. | Retain verified nesting/slot paths; approve narrower payload promises without removing existing contracts. |
| Owned objects/arrays, aliases and writes — **SUPPORTED CANDIDATE** | Component-owned `let` roots: replacement, member/subscript assignment, owned loop iterators/aliases; `=`, `+=`, `-=`, `*=`, `/=`, `%=` require static RHS and entire writable target. Computed indices contribute reads; in-place writes dirty same-scope object roots conservatively. E1, E2, E4, E13. | Flow-insensitive ownership can reject safe copies derived from parameters. Missing/malformed paths, sparse/negative indices, deep alias graphs and full Taskboard mutation composition need proof. | Retain accepted owned paths and conservative invalidation; document false rejections, settle edge semantics before widening. |
| Borrowed mutation and declaration collisions — **UNSUPPORTED** | Correct tested clean-build rejection: writes to component/action parameters, transitive borrowed aliases/iterators, unknown roots, colliding nested declarations. E4, E9. Nested declarations share runtime storage; unique names are required. | Not a language-wide lexical ownership/type system. Safe duplicate names can be rejected; untested provenance shapes remain an audit obligation. | Keep fail-closed diagnostics with file/component/remediation; approve shared-storage restriction publicly. |
| Keyed loops, identity, lifecycle — **SUPPORTED CANDIDATE** | Unique stable string keys with reorder/removal retain Editor state/DOM and release deleted handlers/registry. Large keyed/update/cleanup fixtures supplement E5/E10. | Reference app keys text rows; its editable TaskCards are outside that loop. String-key Editors do not prove editable object rows with duplicate titles. Duplicate/missing/mutable keys and filter/remount need deterministic policy. | Preserve existing keyed contracts; require T0 object-ID composition rather than relabeling failures. |
| Full object-backed Taskboard interaction — **UNVERIFIED** | Owned-write, conditional and keyed tests independently establish useful pieces (E2–E5). [T0 contract](taskboard-acceptance-contract.md) combines them. | No existing fixture demonstrates the complete create/edit/complete/reorder/filter/delete sequence on immutable-ID objects. | Run the independent T0 oracle; accepted builds alone cannot promote this row. |
| Actions and event handlers — **SUPPORTED CANDIDATE** | Named local actions dispatch to their owning instance, survive keyed moves and execute static owned assignments; submit dispatches once. E3–E6. | General event payload typing/coercion, reentrancy, all event kinds and host exceptions are not established. | Retain current click/input/submit cases; define additional payload contracts before promising them. |
| Forms, `into`, focus and selection — **SUPPORTED CANDIDATE** | Component `into` requires a simple local writable `let` name; invalid target validation in E13 and semantic `WarnsOnInvalidComponentIntoTargets` / `WarnsOnSemanticIntoTargetsThatCannotBeWritten`. Native form E6 and `form_focus` E10 prove bounded retained input behavior. | Checkbox/select/number/file, IME, validation, selection direction and focus across object-row reordering are not covered by the native form fixture. Nested/member/derived/missing bindings are outside this contract; broad form typing remains partial. | Retain simple binding/native-submit/focus contracts; require explicit control/coercion evidence for extension. |
| Routing/direct navigation — **SUPPORTED CANDIDATE** | Existing hash routes, startup exactly once, history back/forward, direct `#/about` initialization, unmatched fallback and retained route state. E8. | Clean-path HTTP refresh/rewrite rules, parameter decoding, guards, layouts and route-driven request races are not established by E8. CDP startup installs the real hash before assets; HTTP harness uses navigation. | Preserve tested hash routing; classify wider routes separately and document deployment requirements. |
| Fetch and async states — **EXPERIMENTAL** | Structured fetch options/manifests and browser implementation for loading/data/error, retries/cache/invalidation, route interpolation; E12/E13 and `CapturesFetchOptionsInStructuredRecords` in semantic tests. | No independent service proves persistent CRUD, race ordering, cancellation, retry/timeout/error recovery and credentials together in clean production. | Name specific allowed exploratory shapes; require T1/T2 HTTP scenarios before application claims. |
| Stores and effects — **EXPERIMENTAL** | Recognized semantics and live effect propagation; E12 plus `ComponentDefinitionsExposeOwnedSemantics` in semantic tests; E13. | Live nested-`let` propagation is intentional; do not impose lexical-block semantics from ownership assumptions. Browser scheduling, cleanup, loops and shared-store isolation lack an equivalent application oracle. | Preserve supported backend behavior; decide browser store/effect lifetime and scheduling contracts before promotion. |
| JavaScript/host interoperability — **EXPERIMENTAL** | Explicit `extern` names host window paths; runtime `startExternBindings` resolves a function and reports missing hosts. Linter test `FriendlyExternActionIsKnownAndClientIntercepted` in [linter tests](../../tests/test_linter.cpp), E12/E13. | No complete clean static-component host invocation, async error or ownership/mutation contract is established. Host code can mutate outside observable tracking. | Require a typed/observable host boundary and browser evidence before broad support; keep extern review warnings. |
| Unknown/side-effectful expression calls — **UNSUPPORTED** | E1/E4/E9 test production rejection in conditions and complete assignment RHS/computed lvalues, e.g. `result = input.push(1)` or `items[mystery()].score = 1`. | Correct rejection is verified in those contexts only. Arbitrary calls in all top-level/template/host contexts are an **unaudited fail-closed boundary**, not a claim of universal rejection. | Audit remaining contexts; add negative cases or explicitly document experimental escape hatches before freeze. |
| Browser production versus live/compat — **SUPPORTED CANDIDATE** | Clean split assets default; formal `window.jtml.browserBuild`, no legacy plan asset/global, generated static create/update paths. Explicit `--compat`/`--debug` are separate contracts; E9–E11. Live endpoints and Classic/C API remain supported backends. | Live or compatibility success does not prove clean browser parity. Generic shape validation covers tested nodes, not all possible programs; parity test names can describe metadata/string checks. | Retain mode/schema and backend regressions; no implicit fallback for supported production shapes. |
| Output text, serialized assets, dynamic compilation — **SUPPORTED CANDIDATE** | E11 tests hostile literals/script terminators and omitted explain fields; E9/E10 scan assets for `eval`/`new Function` and legacy bridges. Reference browser renders `<release> & CSP` as text. E13 escapes manifest delimiters and generated string literals. | String scans are not comprehensive CSP/security validation. Full hostile DOM/attribute/URL/serialization corpus across creation and update is missing. | Preserve existing security tests; require the negative security gate below before preview. |
| Untrusted raw HTML/URL safety — **UNVERIFIED** | Explicit raw HTML/CSS escape hatches are recorded/warned (`CapturesRawHtmlEscapeHatches` in semantic tests; `RawEscapeHatchesAreVisibleWarnings` in CLI tests). E13 escapes HTML text/attributes, but that alone does not establish URL scheme policy. | No inspected adversarial URL corpus establishes rejection/sanitization of `javascript:`/dangerous `data:` or raw-HTML trust boundaries. This is an unresolved security/fail-closed audit gap, not a proven exploit or sanitizer guarantee. | Decide trusted-source/host/raw boundaries and allowed URL policy, then prove enforcement. |
| Asset size and deployment limits — **EXPERIMENTAL** | E9/E10 pin existing fixture budgets and public asset copying; E11 tests sensitive/generated file exclusions. Directory symlinks are skipped. Last recorded shared runtime: 271879/272000 bytes (PR #10), not measured anew here. | Reference HTML remains 135374 bytes versus the 70000-byte microfixture comparison; older notes report 135395. Manifest duplication remains. No validated whole-application budget, compression/startup/memory or maintenance baseline. | Keep every existing budget and visible regression; choose realistic application budgets from measurement, not by raising microfixture thresholds. |
| JTL backend/API — **UNSUPPORTED** | [Language-family design](../architecture/language-family-design.md) explicitly leaves mature standalone JTL/backend operations planned. | Not all planned syntax has tested clean rejection: **unverified fail-closed boundary**. No first-party backend/auth promise follows from browser fetch syntax. Framework/custom-element exports retain their separate EXPERIMENTAL status from CURRENT_STATE; they are not downgraded by this row. | Keep future JTL/API work outside v0.3 promises; audit accepted experimental forms rather than claiming mature support. |

## Gaps and contradictions to resolve

1. The pre-PR #10 draft describes stale `if title == "After"` as current. PR #10
   fixes it and adds E2/E3; keep the old report as history and require regressions.
2. The language reference lists a broad “production authoring surface,” including
   calls and control-flow constructs. It documents syntax across backends, not a
   blanket clean-browser guarantee. The candidate matrix must be approved and then
   reconciled with public reference/AI guidance; it must not silently erase support.
3. AGENTS previously said CI lacked browser benchmarks. Current
   [CI](../../.github/workflows/ci.yml) requires E9 on Ubuntu/macOS. It still does
   not run all nine performance browser fixtures or the full local gate. Historical
   CURRENT_STATE CI descriptions describe their dated baseline, not today's workflow.
4. Clean component modules omit source-rich fallback/debug metadata; that does
   not mean the whole HTML manifest is minimal. E9 explicitly reports duplicated
   manifest size. “Clean” is a mode/asset contract, not a size or secrecy guarantee.
5. Object mutation and string-key Editor evidence must not be substituted for
   T0's combined object-backed application. URL security, broad host semantics,
   async races and clean installation remain evidence gaps, not passing claims.

All gates apply to the exact candidate release commit; attach immutable run links,
commands, platform/tool versions, counts, artifacts, failures and skips. Owner
approval is required for decisions, but not for publication on a fixed date.
No external adoption is required before an experimental preview.
