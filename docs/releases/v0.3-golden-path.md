Baseline: `e486cb6` on main, including merged PRs #40 and #41. This slice makes
local experimental artifacts identifiable and independently install-testable.

ABI, or establish production/enterprise readiness.

## Proposed v0.3.0 mapping

| Identity | Development | Local candidate | Proposed final release |
| --- | --- | --- | --- |
| CMake numeric project version | 0.3.0 | 0.3.0 | 0.3.0 |
| `JTML_VERSION_SUFFIX` | dev (default) | rc.2, or the reviewed RC identifier | empty, explicitly selected |
| CLI, C API, doctor, HTTP/LSP version | 0.3.0-dev | 0.3.0-rc.2 | 0.3.0 |
| CPack and CLI archive version | 0.3.0-dev | 0.3.0-rc.2 | 0.3.0 |
| VS Code extension source | 0.2.0, independently versioned | no VSIX in this artifact | separate compatibility/publication decision |

`jtml_abi_version()` retains its existing behavior: it returns the distribution
version. Its historical name is not a promise of binary compatibility between
versions. Compile consumers against the header delivered with the same library.
Python bindings and npm/VSIX dependency redistribution are outside this
Python-off/source-editor artifact contract.

The CLI archive uses `jtml-<full-version>-<os>-<arch>.tar.gz`; the CPack install
layout uses the same name plus `-install`. The source layout in a CLI archive and
the GNUInstallDirs layout in CPack are intentional different containers with the
same executable/library identity. Packagers must not label a dev binary as final.

## Exact local artifact and installation commands

From a clean checkout of the candidate commit, on the target host:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DJTML_BUILD_TESTS=ON -DJTML_BUILD_PYTHON=OFF -DJTML_VERSION_SUFFIX=dev
cmake --build build --parallel 8
ctest --test-dir build -R 'Release\.|CliResources|CApi|StudioSamples|CliDoctor' --output-on-failure
SOURCE_DATE_EPOCH="$(git show -s --format=%ct HEAD)" scripts/package_cli.sh dist/release
cpack --config build/CPackConfig.cmake -B dist/cpack
version="$(cat build/jtml-version.txt)"
archive="dist/jtml-${version}-$(uname -s | tr '[:upper:]' '[:lower:]')-$(uname -m).tar.gz"
python3 scripts/test_studio_distribution.py --archive "$archive" --cpack-archive "dist/cpack/$(cat build/jtml-cpack-filename.txt)"
cmake --install build --prefix /tmp/jtml-install
/tmp/jtml-install/bin/jtml --version
/tmp/jtml-install/bin/jtml check /tmp/jtml-install/share/jtml/examples/friendly_counter.jtml
```

The test creates its own temporary installations outside the repository, removes
the original extraction path by moving it, and uses separate empty HOME/cwd for
each CLI/C consumer. Installed Studio is also launched from an unrelated directory
containing a deliberately empty fake catalog; packaged resources must win. A
symlink launch must resolve the real executable's resources. The C consumer uses
only the delivered header/library and an explicit runtime library search path;
no repository include path, loader override or source fallback is supplied.

To prepare an RC locally, use
`JTML_VERSION_SUFFIX=rc.2 scripts/package_cli.sh dist/release`.
An explicitly empty suffix (`JTML_VERSION_SUFFIX= scripts/package_cli.sh dist/release`)
selects 0.3.0 but does not approve, sign, tag or publish it. The focused CMake test
checks dev/RC/final mapping and rejection of path-shaped suffixes. The tested
binary artifact in this slice is the development identity.

## Reproducibility boundary

`ARTIFACT.json` records version, host OS/architecture, source revision, dirty flag
and source-date epoch. SHA256SUMS covers the manifest and every payload file;
the checksum file excludes itself. MANIFEST.txt uses sorted relative names and
excludes SHA256SUMS. The archive normalizes ordering, ownership, permission modes
and timestamps, and rejects symlinks in the prepared distribution tree. Repacking
the same prepared tree at the same epoch must produce identical archive bytes;
an independent changed-content control must produce different bytes.

This is container reproducibility plus repeatable build/install instructions.
It is not proof that different compilers, SDKs, host libraries or operating
systems produce identical native binaries. SOURCE_DATE_EPOCH does not establish
source authenticity. Dirty artifacts remain identifiable experiments and must not
be represented as a reviewed public release. A final release still requires a
clean reviewed source revision, platform matrix, rights review, signing/checksum
publication policy and artifact promotion procedure.

## Verification evidence

Focused local checks: 13/13 PASS. The three installation paths above each pass
CLI version/check/clean-browser build, bundled examples, a compiled C caller's
version/render call, and Studio resource equivalence. Observed resources are
13 samples, 12 reference entries, 2 sidebar groups, 14 lessons and 14 docs.
Original notices/manifests/checksums remain checked. The stable candidate passed
**471/471 CTests** and the complete local gate once, with **no skips**, nine
benchmarks plus the production reference all reporting `browserExit=clean`, and
live smoke **8/8**. Runtime remains **271855 / 272000 bytes**. Taskboard lint
remains **0 errors / 1 legitimate accessibility advisory**. The gate still records
five native renderer failures and reference HTML **99878 / 70000 bytes**; these
are not newly passing contracts.

The initial new resource-path unit test compared `/var` and `/private/var` strings
on macOS; its fixture root was canonicalized to compare the same physical path.
All assertions remain. Archive tests disable bytecode output so merely running
them does not mark a clean source checkout dirty. No implementation or acceptance
assertions changed after the successful full gate. Detailed final gate results
and artifact digests are recorded in the PR; a green source gate does not imply
hosted CI or release approval.

Run the full source gate once the candidate is stable, with Chromium/Playwright
installed and selected (see the deployment guide):

```sh
JTML_REQUIRE_BROWSER_BENCH=1 JTML_BROWSER_BENCH_REQUIRE_CLEAN_EXIT=1 scripts/verify_all.sh
```

`doctor` is deliberately still a source-layout audit. It reports the consistent
version but is not an installed-package readiness test. Missing resources are not
fabricated by the resolver, and release tests do not change source semantics to
obtain a passing compiler result.
