# JTML v0.3.0-rc.1 — experimental technical tester candidate

These are prepared release notes and tester instructions, **not a publication
announcement**. There is no automatic tag or GitHub release. Packages from the
manual review workflow become distributable only after the owner reviews the
exact source, both platform results and licensing/provenance. Check the workflow
run and ARTIFACT.json for the actual source SHA; a version string alone is not
source authentication. This candidate is not production/enterprise-ready.

## Release scope and blockers

**Automatically verifiable, required before sharing:** build a clean exact commit
as 0.3.0-rc.1; produce both Ubuntu Linux and macOS packages; pass the existing
relocated bundle/CMake/CPack, compiled C API, notices/checksum/manifest and Studio
checks; pass the production-reference browser checks with clean browser exit;
retain matching source/version metadata and download checksums. A failure in either
platform blocks promotion of that platform. A green development build is inherited
baseline evidence, not proof that the RC packages passed.

**Owner decisions, still required:** confirm project/contribution/asset provenance
and rights to distribute the project under Apache-2.0, including the outstanding
JSON-header import/provenance question in the [readiness audit](v0.3-readiness.md#license-and-ownership-audit);
review retained third-party terms; approve the experimental support boundary and
chosen source SHA; decide when/how to distribute the verified files and whether
to perform a separate official tag/release. This workflow records no legal approval
and cannot manufacture one. These decisions do not block generating review files.

**Disclosed limitations, not automatically blockers for this bounded prerelease:**
five native complete-attribute renderer differences; reference microfixture HTML
99878 / 70000 bytes; experimental tooling/type/source-span coverage; unsigned and
unnotarized binaries; no Windows, Linux arm64, Intel Mac, universal macOS, Python
binding or VSIX artifact. The owner must accept this scope explicitly; no budget,
oracle or known-discrepancy catalog is changed to obtain a release pass.

## What's in RC.1

Friendly JTML 2 is the canonical authoring language: observable state/actions,
HTML-shaped UI and static browser output for validated application shapes.
Classic remains compatibility/embedding infrastructure; JTL remains experimental.
This RC packages the already reviewed compiler; it adds no language semantics.

The distribution reuses the existing versioned CLI/C API packaging, relocatable
Studio data, deterministic archive container, complete notices, source identity
and clean-room installation checks. The command below selects rc.1 explicitly;
default source builds remain 0.3.0-dev. The independently versioned 0.2.0 editor
source is included for reference, not a published extension or promised versioned
ABI. `jtml_abi_version()` identifies the same distribution as the CLI.

## Supported and unsupported test contract

| Surface | RC.1 technical testing contract |
| --- | --- |
| Ubuntu Linux x86_64 | Native build/test on `ubuntu-22.04`; no claim for other distros or older glibc/libstdc++ |
| macOS Apple Silicon arm64 | Native build/test on `macos-14`; local machine evidence is macOS 14.4.1 arm64; earlier macOS and Intel are unverified |
| Browser-local output | Four generated assets, counter and production-reference interactions, CSP-safe JS; application support remains bounded by existing production fixtures |
| Studio/tutorial/examples | Bundled resources discovered after relocation; loopback trusted-code tools, not a public server or sandbox |
| C API | Matching shipped header/library and compiled caller smoke; no stable cross-version ABI guarantee |
| check/lint/LSP/fmt/fix | Experimental; Taskboard currently has zero lint errors and one legitimate unlabeled-card advisory; no full typechecker or universal exact spans |
| Native/live rendering | Experimental; five documented attribute differences remain real failures; do not assume browser/native equivalence |
| Packaging reproducibility | Same prepared tree and epoch reproduce archive bytes; identical native binaries across SDKs/toolchains are not claimed |
| Other targets | Windows, Linux arm64, Intel/universal Macs, Python wheels and VSIX are outside this RC distribution |

The workflow uses explicit [GitHub runner labels](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
`BUILD_ENVIRONMENT.txt` records host/compiler versions and dynamic-library
requirements. Runtime C/C++ system libraries remain host dependencies. Signing,
notarization and clean end-user machines are not implied by hosted install smoke.

## Prepare and review exact RC artifacts

After this PR is merged, choose its reviewed merge SHA (or a later reviewed commit
containing these scripts). Run the workflow from the default branch; pass the full
40-character **source commit**, not a moving branch name:

```sh
gh workflow run rc-distribution.yml --ref main \
  -f source_revision=<FULL_REVIEWED_40_CHARACTER_SHA>
```

Use Actions → **RC distribution review** to follow both jobs. No upload step runs
if packaging, installation or browser checks fail. The download groups are named
`jtml-0.3.0-rc.1-linux-x86_64-<SHA>` and
`jtml-0.3.0-rc.1-darwin-arm64-<SHA>` (14-day review retention). Within each group:

- `jtml-0.3.0-rc.1-<platform>-<arch>.tar.gz`: primary tester bundle, extracts to `release/`.
- `jtml-0.3.0-rc.1-<platform>-<arch>-install.tar.gz`: alternative CPack install layout.
- `ARTIFACT.json`, `RC_REVIEW.json`, `BUILD_ENVIRONMENT.txt`, `SHA256SUMS`, these release notes and a feedback form.

The two layouts are alternatives from the existing packagers, not separate
compiler builds. The checksums cover all review payload files, including both
archives; the bundle also contains its own per-file checksums and relative manifest.
They detect changed bytes, not authenticity against a compromised download source.

To reproduce locally from the selected **clean checkout**:

```sh
git checkout --detach <FULL_REVIEWED_40_CHARACTER_SHA>
python3 tests/test_prepare_rc.py
python3 scripts/prepare_rc.py --source-revision "$(git rev-parse HEAD)"
```

The existing packager configures Release, Python off and suffix rc.1, then builds
CLI/C API. CPack runs **before** the final explicit install, preserving its correct
install manifest. All existing distribution tests run unchanged. `dist/rc-review/`
is the review payload; source SHA, dirty state, host and SHA-256 are recorded.
The manual workflow additionally invokes the existing browser reference with the
actual packaged RC CLI. Neither command tags, publishes, enables auto-merge nor
records owner approval. No new competing packaging implementation is introduced.

## Install and five-minute first-app smoke

Download the review group matching your OS/architecture from a successful run,
unzip it into a new directory, and open a terminal there. Compare ARTIFACT.json's
SHA/version with the reviewed workflow source before using the files.

```sh
# Linux:
sha256sum -c SHA256SUMS
# macOS instead:
shasum -a 256 -c SHA256SUMS
```

Every line must report OK. Use the primary bundle (not the `-install` alternative):

```sh
case "$(uname -s)-$(uname -m)" in
  Linux-x86_64) target=linux-x86_64 ;;
  Darwin-arm64) target=darwin-arm64 ;;
  *) echo 'No RC.1 binary for this target'; exit 1 ;;
esac
tar -xzf "jtml-0.3.0-rc.1-${target}.tar.gz"
cd release
./bin/jtml --version
# Must print: jtml 0.3.0-rc.1
./bin/jtml check examples/friendly_counter.jtml
./bin/jtml build examples/friendly_counter.jtml --target browser --out counter-dist
python3 -m http.server 8000 --bind 127.0.0.1 --directory counter-dist
```

Python 3 is only needed here to serve files; the installed CLI does not require
Python, CMake, Node or a C++ compiler to check/build applications. Open
[localhost:8000](http://localhost:8000). Success means **Friendly JTML Counter**,
Count: 0 initially, Count: 1 after **Add one**, then Count: 0 after **Reset**.
The README screenshot is the one-click state of this exact bundled source.
`counter-dist` must contain `index.html`, `jtml-runtime.js`, `components/index.js`
and `app.js`, with no compatibility update-plan file. Stop the server with Ctrl+C.

Then run `./bin/jtml studio --port 8001`; open localhost:8001, select Counter,
format/run it and open a lesson/reference entry. Success means nonempty samples,
lessons and reference/docs; shutdown with Ctrl+C. HTTP/WS bind to loopback (WS
port 8081). Ports must be available. Resources also work when invoking the absolute
binary path from another directory; compiler input/output paths remain explicit.
Unsigned macOS downloads may be blocked by local policy; report the exact message.
`doctor` remains a source-tree audit, not the installed-package acceptance command.

## Feedback and next owner actions

Use the [short feedback template](rc-feedback.md) or the bundled FEEDBACK.md.
Include source SHA, package checksum, OS/architecture, exact command and a minimal
reproducer. Distinguish static browser behavior from native/live rendering. Do not post secrets or private application data.

After merge: run the manual workflow for the reviewed SHA; review **both** job
results, metadata, notices and hashes; record the outstanding owner approvals;
choose the files to share with testers; collect five-minute smoke feedback. An
official prerelease/tag/publication is a separate explicit owner action. Missing
platform or licensing evidence must stay visible; there is no automatic promotion.
